## 0. 一页纸摘要

**《市井烟火 · 百味人间》是一个可以“走进去”的老街叙事网页，不是美食攻略，也不是传统的滚动长页。**

用户从清晨六点四十七分进入一条虚构的武汉老街。拖动火柴点燃炉火后走进街里，用拖拽、滚轮或方向键沿街漫游；街道从清晨菜市场，经过午后老街，一直到深夜烧烤摊。沿途有八个可交互热点：三家早点摊、修表摊、旧海报、檐下的猫、烧烤摊和糖水铺。点击热点会打开一段普通人的故事，并收下一枚“烟火碎片”。

**核心循环：**

`点火 → 走进街里 → 漫游/点击热点 → 读一段故事 → 收一枚碎片（×8）→ 集齐 → 片尾 → 去留言墙留一句`

**为什么是这种形态：**

- 纯展示页只能“看”，用户与街道之间没有回应；
- 完整经营或解谜游戏内容量过大，难以在课程周期内保证一条高质量完整流程；
- “空间漫游 + 轻叙事 + 可带走”的轻交互形态，兼顾完成度、氛围感与现场可演示性；
- 纯前端实现，无需后端，部署与演示成本低。

**差异化公式：**

`空间叙事 + 时间光影 + 八段小人物故事 + 本地留痕`

**当前已实现范围：**

一条包含三个时段的老街、八个热点与故事卡、碎片收集与片尾、漫游进度驱动的动态光影、Canvas 氛围粒子、本地留言墙、收集进度持久化、移动端纵向漫游、旧浏览器静态阅读页。环境音系统已完成接口与控件，音频素材待接入。

**项目目标（可用性测试口径，待执行）：**

| 指标                     | 目标   |
| ------------------------ | ------ |
| 无指导完成率             | 5/5    |
| 首次有效交互耗时         | ≤ 10 秒 |
| 单次完整体验时长         | 3–5 分钟 |
| 能复述至少一个热点细节   | ≥ 3/5  |
| 愿意留下留言或分享       | ≥ 3/5  |
| 彩排无故障连续完成       | 3 次   |

> 用户画像、需求判断与上述指标为初始假设，需在最终提交前通过 5 人可用性测试验证；文档中的数字是目标，不是既有成绩。

## 1. 项目背景与机会

### 1.1 主题转译

“市井烟火 · 百味人间”如果只落在照片与文案上，很容易变成另一条常规的滚动长页。本项目把主题拆成四种可被用户直接感知的体验：

1. **空间**：不是“翻页看内容”，而是“沿一条街走”。
2. **时间**：同一条街从清晨走到深夜，天空、日光、雾气与灯火随之变化。
3. **人物**：八段故事都落在具体的人身上，不写宏大的城市抒情。
4. **痕迹**：用户会带走八枚碎片和一句自己写的留言，而不是看完即走。

### 1.2 为什么聚焦学生

- 在校学生与“老街、早点摊、夜宵摊”有天然的生活记忆，理解成本低；
- 课间、饭后、睡前有 3–5 分钟的碎片时间，适合轻量体验；
- 学生群体对“氛围感、可截图、可分享”的内容有更强的传播意愿；
- 首批验证群体就在身边，便于在一周内完成 5 人可用性测试。

### 1.3 现有替代形式与空位

| 形式             | 优点                 | 不足                                       |
| ---------------- | -------------------- | ------------------------------------------ |
| 图文长页 / 公众号 | 内容承载强、制作快   | 用户始终在“看”，空间感与时间感弱           |
| 城市美食地图     | 信息明确、实用       | 工具属性强，缺少叙事与情绪                 |
| 经营类小游戏     | 参与感强、目标清晰   | 学习成本与内容量高，容易做成“任务清单”     |
| 我们的方案       | 空间漫游、光影变化、人物故事、本地留痕 | 内容量有限，依赖美术与文案质量             |

### 1.4 我们的答案

让用户**用走路的节奏读故事**：没有任务清单、没有失败、没有倒计时。用户只需要沿街走、点开感兴趣的人和物，最后带着八枚碎片和一句留言离开。

## 2. 产品定位

### 2.1 定位陈述

**《市井烟火 · 百味人间》是一款无压力、治愈向的轻交互叙事网页。** 它不是重型游戏，重点在叙事与氛围；不是美食攻略，不提供店铺推荐；也不是城市宣传片，不追求宏大叙事。

### 2.2 设计原则

1. **空间代替分页**：能用“走过去”表达的，不用“点下一页”。
2. **人物代替景点**：每个热点必须对应一个具体的人或一段具体的生活，不写空泛抒情。
3. **漫游代替任务**：不设强制顺序、不做失败判定，用户可随时停下或离开。
4. **交互克制**：点击、拖拽、滚轮即可完成全部操作。
5. **结果可留存**：碎片与留言保存在本地，刷新不丢失。
6. **尊重设备与偏好**：移动端纵向重排；减少动效偏好下关闭惯性、粒子与装饰动画。

### 2.3 创新点

- **漫游进度驱动的连续时间光影**：时间不是三个固定主题，而是随相机位置从 06:47 连续走到 23:30；
- **“街道 + 热点”的空间叙事**：八段故事分散在一条可漫游的街上，而不是并列的卡片列表；
- **碎片册 + 留言墙双留存**：一枚碎片记录摊主的一句话，一句留言记录用户自己的记忆；
- **移动端纵向重排**：同一份内容在手机上变成可上下滑动的热点清单，而不是缩小版桌面街景；
- **旧浏览器静态阅读页**：React 19 无法在 IE 中运行，但八段故事仍可通过 `legacy.html` 完整阅读。

### 2.4 明确不做

- 不做后端、账号、排行榜、多人互动；
- 不做战斗、经营、解谜等重型玩法；
- 不做多结局分支（原二选一方案已裁掉，统一为单段故事）；
- 暂不接入真实录音素材（接口已预留）；
- 不承诺 IE 下的完整交互，仅保证基础阅读。

## 3. 用户研究

### 3.1 主画像

| 维度     | 描述                                                     |
| -------- | -------------------------------------------------------- |
| 身份     | 19–22 岁在校本科生                                       |
| 设备     | 桌面端 Chrome / Edge；移动端 iOS Safari 或 Android Chrome |
| 可用时间 | 课间、饭后、睡前，3–5 分钟                               |
| 内容偏好 | 有氛围感、有具体人物、可截图分享                         |
| 操作习惯 | 不愿读说明书，希望第一屏就能动手                         |

### 3.2 核心需求

1. **放松**：不需要学习规则，不需要赢；
2. **共鸣**：看到自己熟悉的生活细节，而不是被教育；
3. **掌控**：想走就走、想停就停，不被任务推着走；
4. **留存**：体验结束后有东西可以带走或回看。

### 3.3 典型使用场景

- 下课后在宿舍打开电脑，用几分钟走完整条街；
- 等餐、坐地铁时用手机竖屏浏览，随手点开一两个故事；
- 深夜看到烧烤摊一章，想起自己常去的那家店，去留言墙写一句；
- 老师或同学在评审现场观看一次完整演示。

### 3.4 待验证假设

| 假设                                     | 验证方式             |
| ---------------------------------------- | -------------------- |
| 用户能在 10 秒内理解“拖拽漫游”           | 5 人可用性测试       |
| 时间光影变化能被感知，且不会造成阅读干扰 | 访谈 + 观察          |
| 八个热点数量合适，不会让用户觉得“扫点”   | 完成率与访谈         |
| 留言墙能激发表达意愿                     | 留言提交率           |
| 移动端纵向模式比横向缩放更易用           | 两台设备对照测试     |

## 4. 核心体验设计

### 4.1 叙事结构

整条街分为三个时段，共八段故事。时段之间存在“快进”：走过时段交界时，时间会快速推进到下一幕。

| 时段 | 名称       | 时间范围      | 热点                                 |
| ---- | ---------- | ------------- | ------------------------------------ |
| 壹   | 清晨菜市场 | 06:47 — 08:30 | 陈记热干面、周姐豆皮、婆婆豆浆       |
| 贰   | 午后老街   | 14:00 — 17:30 | 老周修表摊、褪色的旧海报、檐下打盹的猫 |
| 叁   | 深夜烧烤摊 | 20:30 — 23:30 | 老李烧烤、深夜糖水铺                 |

### 4.2 街道空间与漫游

- **世界宽度**：桌面端世界总宽 450vw，三个时段各占 150vw；可视窗口 100vw，相机可移动 350vw。
- **时段起点**：清晨 0、午后 3/7、深夜 6/7。这个比例同时用于底部时间轴、光影关键帧与时间换算。
- **桌面操作**：
  - 按住街道拖拽平移；松手后带轻微惯性；
  - 滚轮缩放（0.9–1.15 倍），以视口中心为锚点；
  - `←` / `→` 行走，`Home` / `End` 跳到街首/街尾；
  - 底部时间轴可直接跳到任一时段。
- **移动端**：≤ 820px 自动切换为纵向滚动，三个时段依次堆叠，热点变为可点击的大卡片。
- **性能策略**：相机逐帧只修改 `transform` 与 CSS 变量，不触发 React 重新渲染。

### 4.3 热点与故事卡

- 每个热点是一个原生 `<button>`，可 Tab 聚焦、回车打开；
- 悬浮/聚焦时插画抬升、标签描边；
- 点击后打开故事卡：时段、时间、摊主原话、两到三段故事、碎片印章与摊主原话；
- 首次打开自动收下碎片并播放入章动画；再次打开显示“这枚碎片你已收下”；
- 已收集热点在街景中显示“已收”角标。

**文案约定：**

- 每段故事 2–3 个短段落，单段不超过两行（桌面端）；
- 摊主原话不超过 20 字；
- 不写结论、不写鸡汤，只写动作、物件与一句原话；
- 人物与摊位均为虚构复合创作，不指向具体真实店铺。

### 4.4 烟火碎片与片尾

- 共八枚碎片，对应八个热点；
- 碎片册按三个时段分组展示：已收集显示印章、碎片名与摊主原话，未收集显示“尚未收集”；
- 集齐八枚后，时间推进到 23:30，片尾出现：
  > 这条街睡了。明天六点四十七分，它还会醒。
- 片尾提供三个选择：去留言墙写一句、继续走走、再走一遍；
- “再走一遍”清空收集进度并回到点火序章，留言墙与音效设置保留。

### 4.5 留言墙

- 用户可写下最多 60 字的市井记忆，提交后置顶展示；
- 最多保留 50 条，数据保存在当前设备的浏览器中；
- 条目以纯文本渲染，不使用 `innerHTML`；
- 明确提示“不会上传到任何服务器”，避免隐私误解。

### 4.6 时间光影系统

时间由相机进度换算，关键帧覆盖清晨、上午、午后、傍晚、入夜、深夜六个阶段。每帧插值并写入 CSS 变量，驱动：

| 变量                   | 作用                         |
| ---------------------- | ---------------------------- |
| `--sky-top/mid/low` 等 | 天空五段渐变                 |
| `--orb-x/orb-y`        | 太阳/月亮的位置              |
| `--orb-core/halo`      | 日月光晕颜色                 |
| `--haze-opacity`       | 雾气浓度                     |
| `--window-glow`        | 远景窗灯与摊位窗光           |
| `--lamp-opacity`       | 摊灯、灯泡与暖光             |
| `--stall-brightness`   | 摊位整体明度与饱和度         |
| `--scene-tint`         | 覆盖全场的时段色调           |
| `--vignette-opacity`   | 暗角强度                     |

时间标签从 `06:47` 连续走到 `23:30`，在时段交界处快速跳进。

### 4.7 声音设计

- 三个时段各有一条循环环境音：清晨菜市场、午后老街、深夜烧烤摊；
- 用户点燃炉火的手势用于解锁自动播放权限；
- 切换时段时交叉淡入淡出；HUD 提供全局静音按钮，状态本地持久化；
- **当前版本未接入音频素材**：`src/lib/ambience.ts` 中 `AMBIENCE_ENABLED = false`，不会发起请求；将 `dawn.mp3`、`afternoon.mp3`、`night.mp3` 放入 `public/audio/` 并把开关改为 `true` 即可启用。

### 4.8 视觉方向

| 元素     | 方案                                                           |
| -------- | -------------------------------------------------------------- |
| 主色     | 墨绿 `#15201c`、纸白 `#f4ecde`、炭火橙 `#e0834d`、暗红 `#b64b28` |
| 字体     | 标题用楷体/宋体回退栈，正文用系统无衬线；不依赖外部字体网络     |
| 场景美术 | 纯 CSS + 内联 SVG：摊位、天际线、猫、旧海报、颗粒与暗角         |
| 动效     | 蒸汽、火焰、灯泡呼吸、印章落章；全部可用减少动效偏好关闭       |
| 移动端   | 单列卡片，插画在左、名称与时间在右，触控目标 ≥ 44px            |

### 4.9 可访问性

- 所有热点、按钮、时间轴节点均为原生可聚焦元素；
- 故事卡与抽屉使用 `role="dialog"`、`aria-modal`、焦点陷阱、Esc 关闭，并在关闭后归还焦点；
- 碎片获得通过 `aria-live` 播报；
- 尊重 `prefers-reduced-motion`：关闭相机惯性、Canvas 粒子、印章与装饰动画；
- 装饰性插画统一 `aria-hidden`，避免读屏噪音。

## 5. 用户流程

### 5.1 主流程

```text
加载页面
  → 开场：六点四十七分，拖火柴点燃炉火
  → 炉火亮起：这条街，醒了
  → 点击「走进街里」
  → 老街漫游（桌面拖拽/滚轮/键盘；移动端上下滑动）
  → 点击热点 → 故事卡 → 自动收下碎片
  → 碎片册查看进度（n/8）
  → 集齐 8 枚 → 片尾（23:30）
  → 去留言墙写一句 / 继续走走 / 再走一遍
```

### 5.2 移动端流程

- 进入街景后自动切换纵向布局；
- 上下滑动依次经过三个时段，光影随时间变化；
- 点击热点卡片打开底部故事抽屉；
- 底部时间轴可快速跳到任一时段。

### 5.3 异常与降级路径

| 场景                 | 处理                                                         |
| -------------------- | ------------------------------------------------------------ |
| 浏览器不支持 ES Module / IE | 跳转到 `legacy.html`，提供完整故事的基础阅读             |
| 用户开启减少动效     | 关闭惯性、粒子、印章与装饰动画，保留核心流程                 |
| localStorage 不可用  | 使用内存存储兜底，页面不白屏                                 |
| 存储内容损坏         | `persist` 的 `merge` 校验字段，非法数据回退默认值             |
| 音频素材缺失         | 开关关闭，不发起请求；静音按钮仍可切换并持久化               |
| 窗口尺寸变化         | `ResizeObserver` 重新计算相机边界；跨 820px 断点自动切换布局 |
| 用户直接刷新         | 收集进度、留言、静音保留；序章重新播放，避免跳过点火         |

### 7.3 状态模型

```ts
phase: 'intro' | 'street' | 'ending'
introLit: boolean          // 已点火、尚未进街
collected: string[]        // 已收集碎片
wall: WallEntry[]          // 本地留言
muted: boolean             // 静音
endingSeen: boolean        // 片尾是否已看过
activeHotspotId: string | null
panel: 'fragments' | 'wall' | null
zone: 'dawn' | 'afternoon' | 'night'
```

持久化 key：`shijing-yanhuo:v1`，只持久化 `collected`、`wall`、`muted`、`endingSeen`；阶段每次刷新重新开始，保证评阅时能看到完整序章。

### 7.4 相机与进度换算

- 桌面端：世界 450vw，可视 100vw，最大位移 350vw；
- 进度 `p = cameraX / 350vw`；
- 三个时段起点分别为 `0`、`3/7`、`6/7`；
- 移动端：三个时段各占 1/3 滚动距离，通过 `toStoryProgress` / `fromStoryProgress` 与时间轴进度互相换算；
- 所有位置更新只写 `transform` 与 CSS 变量，React 仅在时段变化时更新。

### 7.5 光影实现

- `src/content/zones.ts` 定义七个关键帧（清晨、上午、午后、傍晚、入夜、深夜）；
- `getLighting(progress)` 对颜色做 RGB 插值，对透明度、位置做线性插值；
- `applyLighting(element, progress)` 将结果写入场景根节点的 CSS 变量；
- 时段变化只在跨过 `3/7`、`6/7` 时写入 store，避免逐帧渲染。

### 7.6 粒子实现

- 单个 `requestAnimationFrame` 循环；
- 清晨：缓慢上浮的雾粒；午后：斜向浮尘；夜晚：从烤摊方向升起的火星；
- 数量分级：桌面 60 / 低核心数 34 / 移动端 24；
- `prefers-reduced-motion`、页面隐藏、无 Canvas 时停止；
- DPR 上限 2，避免高分辨率屏幕过度绘制。

### 7.7 持久化与容错

- `safeStorage` 包裹 `localStorage`：读/写异常时自动降级到内存；
- `merge` 校验碎片 id、留言字段与时间戳，去重并限制 50 条；
- 留言以 React 文本节点渲染，避免 XSS；
- 入口 `#wall-input` 限制 60 字，提交空内容无效。

### 7.8 IE / 旧浏览器降级

React 19、ES Module、`100svh`、CSS 变量等均无法在 IE 中运行，因此采用：

1. `index.html` 中的 `<script nomodule>`：现代浏览器忽略，IE11 执行并跳转；
2. `public/legacy.html`：纯静态、无 JavaScript、无 CSS 变量、无 `clamp()` 的阅读页；
3. 内容包含三段时间与八段完整故事，满足“基础浏览”；
4. 不承诺 IE 下的漫游、粒子、音频与留言墙。

## 11. 展示与答辩

### 11.1 60 秒电梯陈述

> 我们做的不是一条美食攻略，而是一条可以走进去的老街。
> 用户从清晨六点四十七分出发，拖火柴点亮炉火，沿街走到深夜。
> 沿途有八个普通人：热干面摊主、修表匠、一只睡在檐下的猫。
> 每点开一个人，就收下一枚烟火碎片；集齐八枚，街灯熄灭，时间停在二十三点半。
> 整条街的光影、雾气和灯火都随漫游实时变化，手机上则自动变成纵向漫游。
> 所有收集和留言只保存在本地，刷新不丢。

## 12. 风险与应对

| 风险                       | 影响                     | 应对                                                         |
| -------------------------- | ------------------------ | ------------------------------------------------------------ |
| 音频素材缺失或版权不清     | 音频系统无法演示         | 保持接口与静音控件；优先使用可商用素材或自制环境音           |
| IE 兼容预期过高            | 评审认为“未兼容 IE”      | 文档与演示中明确说明降级策略；提供可直接阅读的静态页         |
| 低端设备掉帧               | 漫游卡顿                 | 粒子数量分级、减少动效关闭、只改 transform 与 CSS 变量       |
| localStorage 被禁用        | 进度丢失                 | 内存兜底、界面不报错；演示前检查浏览器设置                   |
| 移动端手势冲突             | 点击热点误触发滚动       | 热点为独立按钮；纵向模式交给原生滚动                         |
| 文案同质化或过度抒情       | 用户记不住人物           | 每段绑定具体动作/物件/原话；可用性测试后统一修订             |
| 现场网络不稳定             | 线上演示失败             | 准备本地构建、离线包与 90 秒录屏                             |
| 时间不足                   | 功能未完成               | 按 6.4 的顺序裁剪，优先保证 P0 闭环                          |
